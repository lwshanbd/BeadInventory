# Silent-Failure Audit — PR #55 (`perf/blob-fetch-mainactor-body-recompute`, commit cddcb2e)

## Findings

### 1. MEDIUM — `try? await Task.sleep` inverts cancellation semantics: cancellation would *run the backup immediately*, not skip it
**Location:** `/Users/baodi/Documents/GitHub.nosync/BeadInventory/BeadInventory/Managers/BackupManager.swift:60-64`

```swift
Task { @MainActor in
    try? await Task.sleep(nanoseconds: 5_000_000_000)
    performBackup(inventoryManager: inventoryManager)
}
```

If this Task is ever cancelled, `Task.sleep` throws `CancellationError` **immediately**, `try?` swallows it, and `performBackup` runs unconditionally — at t≈0, i.e. exactly inside the launch/first-interaction window the 5-second deferral was added to protect. So the failure mode is not "backup silently skipped"; it's worse: cancellation silently *defeats the deferral* and reintroduces the main-thread-heavy fetch+base64 work at the worst possible moment, with zero log trail.

**Mitigating fact (why not HIGH):** the Task handle is dropped, and the only call site (`/Users/baodi/Documents/GitHub.nosync/BeadInventory/BeadInventory/BeadInventoryApp.swift:246`, root `onAppear`) never cancels it — so this path is unreachable today. It is a latent trap for the next person who stores the handle or moves this into a `.task` modifier (which cancels on disappear — and would then fire the backup precisely on view teardown).

**Recommendation:** make cancellation mean "skip" — the code comment already argues skipping is safe (the weekly marker is written only after a successful disk write, so next launch retries):

```swift
Task { @MainActor in
    do { try await Task.sleep(nanoseconds: 5_000_000_000) }
    catch { return }  // 取消 = 跳过本次备份；标记未写，下次启动重试
    performBackup(inventoryManager: inventoryManager)
}
```

Secondary note (LOW): the "already backed up this week" check runs *before* the 5s sleep and is not re-checked after it, so two invocations within the window would both back up. Benign today (single call site per launch; same-day filename overwrites), but a re-check after the sleep would make the function idempotent.
